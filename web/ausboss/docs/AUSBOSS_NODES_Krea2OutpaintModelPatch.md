# Krea 2 扩图模型补丁 🆎

告诉 Krea 2 一张参考图**放在**画布上的**哪里**。用 Krea 2 扩展一张
图片（扩图）时用它，好让模型接着你的图片画，而不是画个只是看起来
相似的东西。

把它放在任何 LoRA 加载器**之后**、采样器**之前**。

原理：参考通常在没有位置信息的情况下到达模型，于是模型把它当作松散
的风格提示，借用外观而重新发明内容。这个补丁把参考钉在拼接器报告的
那个矩形上。

## 控件

节点卡片显示 **Reference**（`source rect` / `whole canvas`）与
**KV cache**（`every step` / `once per run`）。两者都接受连线，并在
工作流重新加载时保留已保存的值。

- **model**：Krea 2 模型。最后打补丁，这样之后加载的 LoRA 不会替换
  被补过的前向。
- **stitcher**：来自 加载图像 + 扩边 🆎 或 图像裁剪 + 旋转 + 扩边 🆎
  节点。它告诉补丁你的图片在画布上的位置。用 局部重绘裁剪 🆎 的
  拼接器时，把 **Reference** 设为 `whole canvas`：在 `source rect` 下，
  参考被钉在裁剪在原图中的位置，而不是铺满裁剪区。
- **KV cache**（`kv_cache`，默认 `once per run`）：每次运行计算一次
  参考的键与值，而不是每步一次。采样期间参考不变化，所以这是白来的
  速度。只在调试、要排除缓存因素时才设为 `every step`。
- **Reference**（`placement`）：参考 token 去哪里。`source rect`
  （`source rectangle`，默认）把它们钉在拼接器报告的那个矩形上。
  `whole canvas` 把它们铺满整帧。哪个对取决于 LoRA——见下文。

## 输出

- **model**：参考 token 已注册进画布网格的模型。

## 两个 LoRA，两种摆放

Krea 2 的基础权重从未在注册参考上训练过；让这个补丁起作用的是为此
训练的 LoRA，而现有的两个想要不同的摆放。

**一次覆盖四边——`whole canvas` + AnyPaint。** yijunwang2 的
[Krea 2 AnyPaint](https://huggingface.co/yijunwang2/krea2-anypaint)
（`krea2_anypaint_rank32.safetensors`）训练时以扩边画布本身作参考，
铺满整帧，已知像素由采样器按住不动。在它的训练里，该参考的新区域
始终是一块平的、取自图片自身中位色的补丁。像 *Krea 2 Outpaint*
示例那样接线：

- 一个任意扩边的扩边节点：如示例里的 图像裁剪 + 旋转 + 扩边 🆎，或
  加载图像 + 扩边 🆎。左、右、上、下同时扩都可以。纯色填充。
- Krea 2 编码 🆎 以扩边节点的 **image** 输出（扩边画布，而不是
  加载图像 + 扩边 未扩边的 *reference* 输出）作参考，
  `vlm_reference` **打开**，并把扩边节点的 **mask** 接进它的 `mask`
  输入。遮罩让编码用图片的中位色重填新区域，与训练时一致。没有它，
  深色或色彩强烈的图片回来时可能把灰色扩边画成一圈灰框。
- 这个补丁设为 `whole canvas`。
- 对扩边画布做 VAE Encode，用扩边遮罩做 Set Latent Noise Mask，并从
  那个 Latent 以全去噪采样。遮罩按住源像素；参考告诉模型它们是什么。

要重绘图片的一部分而不是扩展它，用 *Krea 2 Inpaint Masked* 示例：
局部重绘裁剪 🆎 切出你涂抹的区域，这个补丁用同一个 LoRA 跑在
`whole canvas` 上。加载图像 + 扩边 🆎 本身不接受涂抹的遮罩。

**一次一个轴——`source rectangle` + Registered Outpaint。** 同一作者的
[Registered Outpaint](https://huggingface.co/yijunwang2/krea2-outpaint)
（`krea2_outpaint_rank32.safetensors`）正是这个摆放为之而建的 LoRA：
*未扩边*的源图作为参考接入（加载图像 + 扩边 🆎 的 `reference` 输出，
**VLM reference** 关闭），并被钉在它的矩形上。它训练时的源图横跨
画布的一整个轴——左右扩边时源图必须占满整个高度，上下扩边时它必须
占满整个宽度。一次同时扩两个轴超出它的训练范围，新区域可能崩坏；
节点看到时会在控制台里说明，解法是做两遍：扩一个轴、运行、加载结果、
再扩另一个轴。**一条细条也算。** 另一个轴上有超过 8px 的扩边，比如
拖动留下的几个像素，就意味着源图不再占满它。裁剪 + 旋转 + 扩边 节点
上的 **Align** 与 加载图像 + 扩边 的 **Multiple** 绝不会在你没有扩的
一侧添加细条。警告会报告每个轴上多出来的像素。

没有这两个 LoRA 中的任何一个，补丁仍会摆放参考，但光秃秃的 Turbo
模型只是松散地对待它，结果时好时坏。

## 说明与限制

- **没有参考 Latent 就什么也不发生。** 如果条件里没有带，被补过的
  前向直接调用原来的实现。用 VAE 和一张参考图接上 Krea 2 编码 🆎。
- **它会补丁 comfy 的内部实现。** 摆放会深入 flux 注意力层，所以
  挪动它们的 ComfyUI 版本会专门弄坏这个节点。它在运行时而不是启动时
  导入这些内部实现，所以损坏表现为这个节点上的报错，而不是节点从
  菜单里消失。
- 参考 token 要花注意力。出于这个原因，参考在编码前会被缩小到最长边
  384 px——见 Krea 2 编码 🆎。
