# FlashVSR 放大 🆎

把视频放大并变得更清晰。接入片段的帧，设定放大多少，它返回同一段更细腻的片段。放在保存视频之前当最后一步，生成的片段或你加载的片段都适用。

只需要一个模型文件，不依赖其他包。

## 模型文件

从 [ausboss/FlashVSR-v1.1-ComfyUI](https://huggingface.co/ausboss/FlashVSR-v1.1-ComfyUI) 下载 `flashvsr_v1.1_fp16.safetensors`（3.5 GB），放进 `ComfyUI/models/diffusion_models`。然后刷新页面，或按 `R`，在**模型**里选中它。

这个文件是完整的官方 FlashVSR v1.1 权重。别的 FlashVSR 文件在这里加载不了：节点会停下，并说明缺哪一部分。

## 控件

- **帧数**：片段，以帧批次的形式。加载视频 🆎 的 frames 输出接这里。
- **模型**（`model`）：上面那个模型文件。列表显示 `diffusion_models` 里名字含 FlashVSR 的文件。
- **缩放**（`scale`，初始为 `2`）：每边放大多少倍，1 到 4。设为 `1` 时片段尺寸不变，只做锐化。
- **颜色匹配**（`color_match`，默认开启）：把每帧的颜色拉回你片段的颜色。除非想要模型自己的颜色，否则保持开启。
- **VAE**（可选）：接入 Wan 2.1 VAE 得到更慢、更精细的成片。不接时，由模型文件内置的快速解码器出图。

## 输出

- **frames**：放大后的帧，数量与输入相同、顺序一致。帧率和声音不受影响，所以照旧把加载视频的这两项接到保存视频。

## 效果预期

FlashVSR 会重绘细节：皮肤、头发、布料和边缘都比原片段更锐利。场景、运动和时序保持不变。

长片段并不比短片段多占显存。节点每次只读几帧，内存里只保留最近几帧。

## 技术细节

- **尺寸。** 结果正好是原尺寸乘以**缩放**，取偶数。内部模型按 128 像素的倍数工作；节点为此扩边，算完再把扩边切掉，所以你的画面一点都不会被裁掉。
- **显存。** 576 x 1024 的结果约需 10 GB。空闲显存放不下的结果会切成相互重叠的分块生成再拼接，分块大小按运行时空闲的显存决定。1152 x 2048 在约 16 GB 下分成两块跑完。8 GB 的卡（RTX 3070 Laptop）跑同样的结果会切成更小的块，约 6.5 GB，每帧约 3 秒。
- **速度。** 在 RTX 5090 上：576 x 1024 的结果约每秒 7 帧，1152 x 2048 约每秒 2 帧。
- **单步。** 模型对每组帧只跑一次。没有步数、采样器、提示词或种子可设。
- **模型。** FlashVSR v1.1，作者 Junhao Zhuang 与 OpenImagingLab 团队，以 Apache-2.0 发布。它基于 Wan 2.1 1.3B 视频模型。本节点是包内自带的纯 PyTorch 代码。
- 节点不发网络请求，也不写文件。
