# 加载视频 🆎

从 ComfyUI 的 input 文件夹加载一个视频，作为 `IMAGE` 帧批次，连同它的
音频。一个随尺寸伸缩的播放器显示源视频，并预览选中的裁剪窗口。
拖动它下方高对比度的 **IN** 和 **OUT** 手柄，拖动选中的区间可以整体
挪动窗口，也可以在两个输入框里填一个时间，按秒（`95.5`）或按
时间码（`1:35.5`）。点击选区以外的条带，可以把窗口移到
那个位置。
播放头跟着每一次修改走，所以裁剪时两个边界所在的那一帧都看得见。
在 **来源** 里，列表会静音播放指针下的片段，并随输入即时过滤。

播放被限制在选中的窗口内。**LOOP** 会循环它；关掉循环，
播放到 OUT 就停。重新加载按钮刷新源视频，不会
再开一个预览。播放器用你给节点的高度：
把节点拖高，画面就更大。竖长的视频整幅显示，绝不
被裁掉。

**FRAME** 把加载器切换成取帧模式：裁剪条变成一根
定位轨道，只有标记处的那一帧被加载 —— 一个单图批次，
可以直接交给图像工作流，不必再接一个选帧节点。在轨道上任意位置点击或拖动
即可选择那一帧，也可以在 AT 框里填一个精确时间。
这个模式下播放会自由跑完整个源视频，方便你找
想要的那一刻。选好一帧，IN 会移到那个时间。切回去时，
OUT 留在原处，除非那一帧在 OUT 上或之后：这时 OUT 会移到
视频末尾。

IN 和 OUT 之间的标签说明一次运行实际会加载什么 —— 例如
`0:04.0 of 0:10.0 · 48 frames @ 12 fps`，或 FRAME 打开时的
`1 frame at 0:05.2`。预览无法重新渲染 `every_nth` 的抽帧或 `max_frames`
的上限，所以它改为数出来：帧总数和播放速率取自
源视频的真实帧率（从文件探测，因为浏览器的播放器
从不暴露它），再套用 `every_nth` 和 `max_frames`。当某个
起决定作用的值是从连线来的，或者帧率探测不到时，计数
就不显示，而不是去猜。

## 把视频拖到节点上

把视频文件拖到这个节点上，它就成为节点的源文件：文件被
复制进 ComfyUI 的 input 文件夹（重拖相同内容会复用已有的
副本）并选中，画布上的其他东西都留在原处。如果这个
文件是保存视频 🆎 存出的 mp4 或 mov，里面嵌入的工作流也会被读取，
它的加载视频节点存下的裁剪、`every_nth`、`max_frames`、尺寸和 FRAME
取值会恢复到这个节点上 —— 片段按当初加载的样子
重新打开。同一个文件拖到空白画布上则保持原来的含义：
嵌入的工作流替换整张图。

## 控件

- **来源**（`video`）：input 文件夹里的一个文件；**上传** 可以添加新的。
  ComfyUI 生成的视频，名字形如 `clip.mp4 [output]`，也能加载。
- **IN**（`start_seconds`）：跳过这个时间之前的一切。
- **OUT**（`end_seconds`）：在这个时间停下；`0` 表示源视频末尾，直到你
  移动了手柄。
- **每隔 n 帧**（`every_nth`）：每这么多帧保留一帧 —— `2` 让帧数减半。
  `fps` 输出会相应做除法，所以下游片段仍然按真实速度
  播放。
- **最大帧数**（`max_frames`）：保留这么多帧之后停下；`0` 加载
  整个裁剪窗口。用它给长片段压住内存 —— 解码会提前结束，
  而不是先加载再丢弃。
- **LOOP**：预览时重复选中的窗口。它初始为开，
  并随工作流保存。
- **FRAME**（`single_frame`）：只加载 IN 处那一帧（FRAME 打开时
  该字段显示 **AT**），作为单图批次；它打开时，`end_seconds`、
  `every_nth` 和 `max_frames` 都被忽略。
- **↻**：重新加载选中源的预览。
- **宽度** / **高度**（`custom_width` / `custom_height`）：`0` 保持
  源尺寸。只设一侧，另一侧跟随宽高比，
  并取整到偶数。

## 输出

- **frames**：裁剪后的 BHWC 帧批次。
- **audio**：同一个裁剪窗口；文件没有音轨时是一段静音。
- **frame_count / fps / width / height / duration**：给视频合成节点
  和信息显示准备的现成接线。`fps` 是源帧率除以
  `every_nth`；`duration` 覆盖返回的帧，而不是整个文件。
- **video**：指向同一段裁剪、原生尺寸的惰性核心 `VIDEO` 句柄。
  可以直接接到核心的视频节点，不必再生成
  一个帧批次。`every_nth` 对它不生效 —— `VIDEO` 连线
  原样携带源视频 —— 不过 `max_frames` 的上限会缩短它的窗口，
  与保留的帧数一致。没有 `VIDEO` API 的旧版 ComfyUI 核心返回不了
  句柄；原来的七项输出保持不变。

裁剪窗口是直接解码的 —— 视频中未裁剪的部分从不会
加载进 `frames` 输出，而 `video` 输出保持惰性，直到
有下游消费者向它索取。

## 运行过程中

解码在 ComfyUI 的执行线程之外进行，所以加载长裁剪时服务器仍然
在响应。只要源声明了帧数，节点就逐帧填充进度条，
**Cancel** 会在一帧之内停掉解码，而不是等到
文件末尾。
