# 与源图重新对齐（实验性 🧪） 🆎

把编辑过的图重新对回原图。

Qwen Image 2.1 常常把编辑画得略微放大或偏移，风格类改动尤其明显，比如水彩或动漫。
把编辑盖在原图上，它就对不上了：地平线偏低，脸大了一点。这个节点测量编辑移动了多少，
再把它挪回去。

## 快速上手

1. 把编辑接进 `edited`，原图接进 `source`。
2. 想要最好的结果，就在编辑之前留出边距：用 **加载图像 + 扩边 🆎** 给图扩边
   （`mirror` 填充，每边 64 px），对扩边后的图做编辑，再把它的 `stitcher` 接到
   这里。这样编辑有移动的余地，而你拿回的图一直到边缘都是真实画面。
3. 把 `report` 接到 **显示文本 🆎**，看它测到了什么。

在用 Qwen Image 2.1 的一致性 LoRA？那就跳过边距：LoRA 已经把编辑按在原地，
这个节点只是把剩下的那点偏差修掉。

**实验性：** 在 Qwen Image 2.1 的编辑上测过。这些设置从此保持名字不变；
它怎么测量可能还会改进。

## 它修什么，不修什么

- **修：** 整幅画被放大或平移。地平线、立柱和脸都回到原来的位置。
- **不修：** 编辑重新画到新位置上的东西。一张水彩把船挪了位置，船就留在它画的地方，
  所以结果是贴近对齐，而不是逐像素对齐。
- **放过：** 测不出来的图，或者在算上扩边重构之后缩放超过**最大缩放**的图。那种图
  只会被缩放后输出，报告会说明原因。

## 控件

- **edited**：编辑后的图。
- **source**：你编辑的那张原图，尺寸是编辑模型看到它时的尺寸（在 Qwen Image 2.1
  Edit + Realign 示例里，就是 图像缩放 的输出）。结果按这个尺寸输出。对一批图或
  一段视频，给一张源图，或者每帧一张。
- **stitcher**（可选）：编辑前给图扩过边时，来自 **加载图像 + 扩边 🆎**。
  **图像裁剪 + 旋转 + 扩边 🆎** 也可以。**局部重绘裁剪 🆎** 的 stitcher 在这里不适用。
- **Fit**：`zoom + shift`（默认）修 Qwen 常见的漂移。`affine` 还会修轻微的倾斜。
- **空白填充**：编辑滑过边缘时，会留下一条什么都没有的窄带。`edge`（默认）把最近的
  像素拉伸进去，`source` 用原图填，`gray` 填平灰以便局部重绘。边距足够大时就没有
  这条带。
- **最大缩放**：缩放的百分比上限（默认 20）。对扩过边的图，为了填满边距而放大可以
  额外放宽；这个设置限制的是超出那部分的缩放。缩小仍然按这里写的上限算。超出这些
  限制的都被当作你有意做的改动，原样放过。

## 输出

- **image**：对齐到原图、并且是原图尺寸的编辑。
- **empty_mask**：对齐后的编辑什么都没有的地方为白色（滑出边缘的那条带），其余为
  黑色。把那条带裁掉，或者对它做局部重绘。
- **report**：一行说明它测到了什么，例如
  `realigned: zoom x -0.25%, y +5.24%; shift x +1.0, y +30.1 px; worst corner 61.1 px (142 of 162 areas agree, fit error 3.2 px); warped once; empty strip 5.0% of the frame; to keep real picture there, pad the source before editing: bottom 77 px`
  - **zoom** 和 **shift**：编辑被画大了多少，以及它移动了多远。
  - **worst corner**：移动最多的那个角移动了多远，按像素计。
  - `cut out whole, no resampling`：编辑只需要挪回去，所以它的像素没被碰过。
    `warped once`：它还需要缩放，一步做完。
  - **empty strip**：有多大一部分图最终什么都没有。它点名某一侧和像素数时，
    下次就把那一侧扩那么多。接了 stitcher 时，它会说“边距太小”，以及该加多少。
  - 被放过的图读作 `left as is:` 加原因。
  - 一批图或一段视频每帧一行，都以 `frame N:` 开头。

## 为什么会这样

Qwen Image 2.1 重画大范围编辑时，比例会略微不同。水彩、动漫和油画类的编辑回来平均
高约 4%，最多 12%：在 1 MP 的图上边缘处是 30–40 px，最多到 90。它随种子和提示词
变化，把尺寸吸附到 32、64 或 112 也没用。轻量编辑（改个颜色、“保持原样”）稳定在
0.4% 以内。另外，采样器要接在 Qwen 编码器自己的 `latent` 输出上：换一个其他尺寸的
画布，模型会把整幅图缩小去适配，那是另一种缩放，这个节点本来就不负责撤销它。

## 提示

- 给 `source` 喂编辑模型看到的那张图（或者接上它的 stitcher），并让采样器留在
  Qwen 编码器自己的 `latent` 输出上。
- **用一致性 LoRA 时：** 不需要边距。
- **不用时：** 用 加载图像 + 扩边 的 `mirror` 填充每边扩 64 px，并接上 stitcher。
  镜像扩边看起来像场景的延续；平灰或拉伸的边缘像素看起来像边框，模型更可能为了
  填满它而放大。1 MP 下 64 px 的边距大约多花 27% 的渲染时间。
- 每个种子的漂移都不一样。空带太宽时，换个种子往往漂移更小。
- 轻量编辑（改个颜色、小修补）上，报告里缩放小于 0.5% 就说明模型基本没动。

## 技术细节

本页剩下的部分是给想了解它怎么工作、怎么被测试的人看的。

### 怎么测量

两张图都变成边缘图（梯度强度，按周围归一化），所以换了风格、换了打光、色调反了
也能对上。分块用带限相位相关比较：先在长边 256 px 上找出漂移，把编辑按估计值
变形之后再在 768 px 上做两次，这样分块是在同一尺度上比较的。第一遍在编辑本身就
对不上时，还会试几个缩放（0.86x 到 1.28x），所以像重新取景那样的大幅缩放也能
找到。稳健拟合把分块位移变成缩放和平移；与它相差超过几个像素（最多 8）的分块，
比如重画的船或新加的云，会被排除。至少 10 个分块、且其中至少四分之一一致时，
才采信这个拟合。接了 stitcher 时，分块只铺满图的面积。

对扩边后的重构，每个轴上额外的放大放宽量是画布尺寸除以源图尺寸再减一。它被加到
**最大缩放**上；缩小没有额外放宽。

它在 CPU 上跑，每 1 MP 帧不到一秒。没有新依赖，也不用模型。

### 实测

- **植入的漂移**（每个轴最多 12% 的缩放、平移、带 affine 的轻微旋转、换风格的副本、
  另一分辨率下的编辑；带边距时，还有几乎填满画布的 27–33% 重构）：在角上恢复到
  约 0.1 px 以内，重构约 0.2 px。没有粗粒度那一遍的缩放尝试时，30% 的缩放会丢
  （偏 137 px）；有它就能找到。
- **166 次真实的 Qwen Image 2.1 编辑**，四张图：测出 164 次。被放过的两次是在
  1024x1024 画布上为一张 832x1216 的图采样的（画布不对的挤压），报告会点明这一点。
  对齐之后用另一个估计器复测，94 次风格编辑的最差角从 35.5 px 降到 4.6 px（中位数）；
  轻量编辑从 2.1 px 降到 0.1 px。
- **边距，16 次留出的编辑**（12 次换风格，4 次轻量编辑；每个一个种子，64 px 边距，
  对齐后再对着源图复测）：

  | 设置 | 之前的最差角（中位数） | 之后（中位数 / 最差） | 有空带的帧 |
  |---|---|---|---|
  | 无边距 | 40.0 px | 0.10 / 5.8 px | 16 中的 13 |
  | 镜像边距 | 24.0 px | 0.42 / 5.6 px | 16 中的 1 |
  | 边缘像素边距 | 61.2 px | 0.52 / 5.5 px | 16 中的 6 |
  | 灰色边距 | 43.1 px | 0.81 / 9.1 px | 16 中的 5 |
  | 一致性 LoRA，无边距 | 1.5 px | 0.06 / 0.4 px | 16 中的 10（中位数 0.2%，最差 2.7%） |
  | 一致性 LoRA + 镜像边距 | 1.8 px | 0.31 / 3.4 px | 16 中的 0 |

  镜像扩边让模型在 16 次编辑里有 2 次为了填满画布缩放超过 8%，用边缘像素时是 7 次，
  用灰色时是 5 次（有一次它把灰色画成了水彩的纸边）。用 LoRA 时，边距仍然诱使一次
  编辑去放大，而不扩边的 LoRA 路线是最精确的 —— 这就是提示里说用 LoRA 时不要边距
  的原因。
