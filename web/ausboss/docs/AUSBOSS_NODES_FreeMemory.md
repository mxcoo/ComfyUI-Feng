# 释放显存 🆎

原样透传任何内容，同时在途中释放显存。把它放在两个重负载步骤之间——
视频解码之后、放大之前——好让第二步从空闲显存开始，而不是从显存不足
的报错开始。

## 控件

- **value**：任意连线——节点的输入与输出是通配类型，所以它能接进
  `IMAGE`、`LATENT`、`MODEL` 或任何其他连接，无需转接。

## 输出

- **value**：输入，原样透传。

## 行为

- 它按顺序释放：卸载 ComfyUI 已加载的模型，清空 ComfyUI 自己的缓存，
  回收 Python 垃圾，清空 CUDA 分配器缓存。
- 每个释放步骤都是尽力而为。如果 ComfyUI 挪动或重命名了其中某个 API，
  那一步被跳过，连线照常流动；节点绝不会成为工作流失败的原因。每次
  运行实际释放了什么都会打印到控制台。
- comfy 的导入发生在节点运行时，而不是包加载时，所以核心变动表现为
  一个被跳过的步骤，而不是节点从菜单里消失。
- 和任何节点一样，它只在输入变化时运行——它不强制重新执行，所以插入
  它绝不会破坏 ComfyUI 下游的缓存。释放发生在确实有工作流经的那些
  运行里。
- 在这里卸载的模型会被下一个需要它们的节点重新加载；重新加载要花
  时间，这是换取释放显存的代价。
